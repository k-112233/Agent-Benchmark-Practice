# Agent Evaluation

## 1. 评测对象不是“答案文本”

Agent Evaluation 的对象通常是一次完整任务执行，而不仅是最终自然语言回答。

一个 Agent 可能需要：

- 观察环境；
- 制定步骤；
- 调用工具；
- 修改文件；
- 执行命令；
- 处理错误；
- 最终留下可检查的结果。

因此，评测重点应落在**目标是否真正完成**。

## 2. 三个常见层次

### 结果层

直接判断最终状态。

例如：

- 指定文件是否生成；
- 输出数据是否满足要求；
- 测试是否通过；
- 服务是否达到目标状态。

这是最重要的一层。

### 过程层

检查执行过程是否满足限制，例如：

- 是否使用允许的工具；
- 是否超时；
- 是否发生环境错误；
- 是否违反操作限制。

过程信息适合解释失败，但不应轻易替代结果验证。

### 汇总层

把多个 Trial 汇总为指标，例如：

- Pass Rate；
- Failure Count；
- Timeout Count；
- Runtime；
- 各类 Failure Type 的分布。

## 3. Verifier 的作用

Verifier 是判断任务是否成功的核心组件之一。

理想的 Verifier 应：

- 检查真正重要的目标；
- 尽量避免依赖表面文本；
- 对正确结果不过度苛刻；
- 对错误结果不过度宽松；
- 结果稳定、可重复。

例如，若任务要求生成结构化文件，Verifier 更适合检查文件内容和结构，而不是检查 Agent 是否在回答中写出“已完成”。

## 4. Reward 与 Report

不同系统可能采用不同结果表达方式。

一个简化模型可以是：

```text
Trial
├── status
├── reward / score
├── runtime
├── verifier result
└── failure information
```

其中：

- **Reward / Score** 表示任务表现；
- **Report** 提供更详细的执行和失败信息。

公开学习时，应区分“最终指标”与“用于诊断的详细信息”。

## 5. 可重复性

同一个 Agent 对同一任务重复运行可能得到不同结果，因此只运行一次通常不足以完整描述能力。

如果条件允许，可采用：

```text
Task A × N trials
Task B × N trials
...
```

再汇总成功率和失败类型。

## 6. 评测中的常见问题

- Task 本身不可解；
- 环境缺依赖；
- Verifier 漏检；
- Verifier 误杀正确答案；
- 成功标准存在歧义；
- 单次 Trial 被误当作稳定能力；
- 环境错误被算成模型能力错误。

这些问题说明：**Agent Evaluation 同时是任务设计问题、工程问题和统计汇总问题。**

> 本文是学习性总结，不对应任何单一 Benchmark 的官方实现。
