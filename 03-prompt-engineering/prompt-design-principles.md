# Prompt Design：先把任务说明写清楚

## 1. Prompt 在这里做什么

在练习 Agent 任务时，Prompt 可以用来告诉模型：目标是什么、能用什么材料、有哪些限制、最后要交什么。

但 Prompt 不是质量保证。生成出来的文件、代码和测试仍然要自己检查并实际运行。

## 2. 一个够用的组成方式

| 部分 | 作用 | 例子 |
|---|---|---|
| Context | 交代必要背景 | 这是一个配置修复任务 |
| Objective | 说明最终目标 | 让全部给定测试通过 |
| Inputs | 列出可用材料 | `config.json`、测试文件 |
| Constraints | 写明限制 | 不能修改输入文件 |
| Output | 说明产物 | 修改后的配置或代码 |
| Checks | 说明自检方式 | 运行指定测试命令 |

不需要为了“完整”把每一项都写成长段落。能消除关键歧义就够了。

## 3. 抽象词尽量换成能检查的要求

比较下面两组写法：

```text
较模糊：
请保证代码质量较高。
```

```text
更具体：
如果配置缺少必需字段，程序应返回非零退出码。
```

或者：

```text
较模糊：
不要遗漏重要文件。
```

```text
更具体：
最终目录必须包含 README.md、config.json 和 tests/。
```

越能转换成测试，越容易判断任务是否真的完成。

## 4. 多文件任务要先列清单

如果希望模型生成多个文件，可以先列：

```text
需要生成：
- app.py：主程序
- config.json：配置
- tests/test_app.py：测试
```

再说明文件之间的关系。只说“生成一个完整项目”，模型很容易自己补出你没打算要的结构。

## 5. Prompt 和 Verifier 要互相对应

Prompt 负责告诉 Agent 要完成什么，Verifier 负责检查最后是否完成。

```text
Prompt 中的重要要求
        ↓
应该能找到对应的检查证据
```

模型自己说“已经满足要求”不能算通过证据。

## 6. 关于官方项目贡献

这里讨论的是一般学习场景下的 Prompt 写法。Terminal-Bench 当前的贡献规则对部分内容有人类作者要求，因此如果真的向官方项目提交任务，需要单独阅读它最新的 `CONTRIBUTING.md` 和相关说明，而不是照搬本章模板。
