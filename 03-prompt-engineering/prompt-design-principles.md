# Prompt Design Principles

## 1. Prompt 在任务生产中的作用

Prompt 是向模型提供目标、背景、约束和输出要求的指令载体。在 AI 辅助任务设计中，Prompt 不只是要求模型“生成内容”，还需要限定生成范围、明确文件职责、要求可验证的结果，并减少歧义。

Prompt 不能替代设计者对结果的检查。模型生成的任务包、代码和测试仍需经过人工审阅与实际运行验证。

## 2. Prompt 的通用组成

以下是本仓库用于练习的提示词组织方式，不是某个模型或平台的强制格式。

| 部分 | 目的 | 需要说明的内容 |
|---|---|---|
| Role / Context | 提供工作背景 | 模型要扮演什么角色、处理什么问题 |
| Objective | 定义目标 | 最终需要完成什么 |
| Inputs | 提供材料 | 可使用的数据、文件和上下文 |
| Constraints | 限制范围 | 禁止事项、技术限制、格式要求 |
| Output Format | 定义交付形式 | 文件、目录、代码或结构化文本 |
| Quality Criteria | 定义质量标准 | 正确性、完整性、可运行性、可验证性 |
| Self-check | 要求自检 | 生成后检查哪些内容 |

## 3. 约束表达

约束应尽可能具体、可操作、可检查。

较弱的表达：
- “请确保代码质量较高。”
- “注意不要遗漏重要内容。”

更明确的表达：
- “所有输入文件路径必须相对于项目根目录。”
- “如果配置文件缺少必需字段，应返回非零退出码。”
- “输出报告必须包含检查项、检查结果和失败原因。”

明确约束有助于减少模型对“质量好”“完整”等抽象词语的自由解释。

## 4. 输出格式

当模型需要生成多个文件时，应明确文件清单、每个文件的职责、文件之间的引用关系、文件内容格式、是否允许额外文件，以及生成完成后需要执行的自检。

避免只要求“生成完整项目”，却不说明项目结构和各文件之间的关系。

## 5. Prompt 与验证

Prompt 中提出的关键要求应尽量能够被后续检查验证。可以把要求拆成：

1. 可由静态检查验证的内容，例如文件存在、格式正确、配置字段合法。
2. 需要运行验证的内容，例如脚本能否执行、测试是否通过。
3. 需要人工判断的内容，例如任务是否有实际价值、说明是否清晰。

不能把模型的自我声明当作任务通过的充分证据。
