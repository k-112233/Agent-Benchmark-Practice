# 模型评测：从单次运行到可比较的结果

## 1. 评测对象与实验条件

Agent 评测关注 Agent 在给定任务、环境和配置下完成目标的表现。结果不仅受模型本身影响，也可能受到 Agent 框架、工具权限、提示词、环境、时间限制和外部服务影响。

比较结果时必须明确实验条件，不能仅凭一个成功率数字断言某个模型在所有场景下更强。

## 2. Trial 与 Job

在 Harbor 的术语中：
- **Trial**：某个 Agent 在某个任务上的一次执行记录。
- **Job**：由多个 Trial 组成的评测作业，可以覆盖多个任务、Agent 或尝试次数。

## 3. 常用指标

### 成功率（Success Rate）

\[
\text{Success Rate}=\frac{\text{成功的有效试验数}}{\text{有效试验总数}}
\]

必须明确分母如何定义。若基础设施错误、取消任务或无效运行被排除，应报告排除规则和数量。

### 任务通过率（Task Pass Rate）
同一任务运行多次时，可以统计至少一次通过的任务比例，或要求多次运行均通过。两种定义回答的问题不同，报告时必须说明。

### 平均运行时间

\[
\bar{t}=\frac{1}{n}\sum_{i=1}^{n}t_i
\]

平均值容易受极端值影响，必要时同时报告中位数、分位数和超时比例。

### 资源消耗
根据评测目的记录 token、CPU、内存、执行时间或外部调用次数。只有采集口径一致时，这些指标才适合横向比较。

### 失败类型分布
按任务未完成、部分完成、超时、环境错误、验证器错误等分类统计，帮助理解成功率背后的原因。

## 4. 评测设计中的控制变量

比较两个模型或 Agent 时，尽量保持以下条件一致：
- 任务集合和任务版本；
- 环境镜像与依赖；
- Agent 工具权限和配置；
- 提示词和执行参数；
- 超时与资源限制；
- 试验次数和重试规则；
- 验证器版本。

否则结果差异可能来自实验设置，而不是模型能力。

## 5. 多次运行与波动

Agent 任务可能具有随机性。单次成功不能代表稳定能力，单次失败也不能代表必然失败。对关键任务进行多次独立运行，并报告运行次数、成功次数、成功率、波动、超时和错误情况，以及是否使用相同初始状态。

样本量较小时，应避免过度解读细微的成功率差异。

## 6. 结果分析结构

1. **总体结果**：任务数、Trial 数、成功率和运行时间。
2. **任务维度**：哪些任务稳定通过，哪些任务反复失败。
3. **Agent 维度**：不同 Agent 的表现差异。
4. **失败维度**：失败类型和集中出现的问题。
5. **实验条件**：环境、配置、超时和验证器是否一致。
6. **局限性**：样本量、任务覆盖范围和外部依赖。

结论必须限定在实际测试覆盖的任务和条件范围内。

## 7. 本章练习

使用自建合成数据创建评测结果表，至少包含：

```text
task_id, agent, trial, status, runtime_seconds, failure_type
```

计算总体和分 Agent 成功率；按任务统计多次运行结果；统计失败类型；比较平均运行时间和中位数；写出三条结论，并说明数据不能支持哪些更宽泛的判断。
