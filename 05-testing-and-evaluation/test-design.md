# 测试设计：把任务目标转化为可检查的证据

## 1. 测试的作用

任务说明描述 Agent 应完成什么，测试判断最终状态是否满足要求。测试应检查任务要求的行为和结果，而不是强制 Agent 使用某条特定命令或操作路径。

一个测试至少要回答：检查什么、如何检查、什么结果通过。

## 2. 从任务要求提取测试点

| 任务要求 | 可观察证据 | 测试方式 |
|---|---|---|
| 创建指定文件 | 文件存在 | 检查路径和文件类型 |
| 写入指定内容 | 文件内容 | 读取并比较 |
| 输出结构化数据 | JSON / CSV | 解析字段、类型和取值 |
| 实现某项功能 | 程序运行结果 | 正常输入与边界输入测试 |
| 保留原始数据 | 原始文件状态 | 比较内容或校验值 |

测试覆盖表可发现两类问题：要求未覆盖，以及测试检查了任务说明没有要求的行为（测试越界）。

## 3. 测试层次

- **文件与结构检查**：文件是否存在、目录结构是否正确、格式是否可解析。
- **内容与数据检查**：文本、JSON、CSV、数值结果；注意编码、字段类型、缺失值和精度。
- **行为测试**：执行程序或提供输入，观察输出和副作用。
- **边界与异常测试**：空输入、缺失文件、非法格式、极端数值和重复数据。

## 4. 简单示例

假设任务要求在 `/workspace/result.txt` 中写入 `completed`：

```python
from pathlib import Path

def test_result_file_exists():
    path = Path("/workspace/result.txt")
    assert path.is_file()

def test_result_content():
    path = Path("/workspace/result.txt")
    assert path.read_text(encoding="utf-8").strip() == "completed"
```

这里检查文件存在和内容正确，不检查 Agent 具体使用哪条命令，因为执行路径不是任务目标。

## 5. 测试质量要求

- **相关性**：每项测试对应明确的任务要求。
- **充分性**：重要要求有测试覆盖。
- **确定性**：相同输入和状态下结果稳定。
- **可解释性**：失败时能定位具体检查点。
- **独立性**：测试之间尽量不依赖执行顺序。
- **抗投机性**：检查真实结果，而非容易伪造的表面标记。
- **效率**：测试耗时与任务规模相称。

避免只检查源码中是否出现某个函数名、关键词或导入语句；这不能证明实际行为正确。

## 6. 测试失败分类

| 类型 | 典型表现 |
|---|---|
| 目标未完成 | 结果缺失或不符合要求 |
| 部分完成 | 部分测试通过 |
| 任务歧义 | 多种合理理解导致不同结果 |
| 环境问题 | 依赖、容器、权限或网络故障 |
| 测试问题 | 测试本身错误、过严或不稳定 |
| 超时 | 在时间限制内未完成 |
| 验证基础设施错误 | 测试未正常执行或结果文件缺失 |

测试失败不一定等于 Agent 能力不足。

## 7. 本章练习

1. 写出 3—5 条明确的自建任务要求。
2. 为每条要求设计可观察证据。
3. 建立“要求—证据—测试”对应表。
4. 准备正确结果和至少两个错误结果。
5. 分别运行测试，检查能否正确区分。
6. 加入一项任务说明未提及的测试，分析其公平性问题。
